## 先理解這套系統在做什麼

一個包裹到公司櫃台後,它的生命週期是:

```
   送達           登記            通知              領取
    │              │               │                 │
  快遞放下 ──▶ 櫃台拍標籤 ──▶ 本人收到訊息 ──▶ 來櫃台簽名帶走
                   │
              AI 讀出收件人、
              單號、寄件人
                   │
              櫃台看一眼確認
```

**設計上最重要的一句話:AI 負責填空,人負責決定。**

AI 讀錯的成本必須是「櫃台改一個欄位」,而不是「包裹送錯人」。所以每一件都會經過一個確認畫面,低信心的欄位會標黃提醒。系統不會自動確認任何東西 —— 這不是還沒做,是刻意的。

---

## 四種角色

| 角色 | 誰 | 能做什麼 |
|---|---|---|
| **管理員** | IT / 行政主管 | 全部功能 + 員工名錄、使用者、部門、AI 設定、Webhook、稽核紀錄 |
| **櫃台** | 收發室、前台 | 登記、領取核銷、交寄、查詢、報表。看得到機密件 |
| **員工** | 一般同事 | 只看得到**自己的**郵件、綁定自己的通知管道、查自己的取件碼 |
| **唯讀** | 稽核、主管 | 只能查詢與報表,不能改任何東西。**看不到機密件** |

角色決定的不只是選單,而是**看得到什麼資料**。員工登入後查不到別人的件;唯讀帳號連機密件的照片都打不開。

## 管理員:上線前要設定的四件事

順序有意義 —— 每一步解鎖下一步。

### 1. 員工名錄(必要,不然什麼都跑不動)

**管理後台 → 員工名錄**。可以 CSV 匯入或手動新增。

沒有名錄,姓名比對就沒有對象可比,AI 讀出「王小明」也不知道是誰。

**務必填別名/綽號。** 台灣辦公室很多信是靠綽號在流通的,模糊比對會一起比對別名。一個叫「陳建宏」但大家都叫他「阿宏」的人,如果名錄裡沒有「阿宏」,寄給阿宏的東西就對不上。

### 2. 部門 + 每個部門的固定聯絡人

**管理後台 → 部門管理**。

這一步是為了「**部門件**」:信封上寫的是公司名或部門(「財務部 收」)而不是人名。系統會比對到部門,然後通知**那個部門的固定聯絡人**來領。

**沒有設聯絡人的部門,收不到部門件的通知** —— 系統不知道要通知誰,那件會安靜地躺在櫃台。

### 3. AI 供應商

**管理後台 → AI 設定**。

**你要自己準備 API 金鑰**,這個專案不含也不代付任何 AI 費用。支援 OpenAI / Anthropic / Google Gemini / OpenRouter,以及**本地 Ollama**(照片完全不出公司)。

在這裡填的金鑰會加密存放,跟個資用同一套金鑰機制。建議在這裡填,不要寫在 `.env`(那是明文躺在磁碟上)。

可以設定多家並排優先度,前一家掛了自動轉下一家 —— 值得設,不然某家供應商當機的那個下午,櫃台就完全沒辦法登記了。

細節見 [AI-PROVIDERS.md](AI-PROVIDERS.md)。

### 4. 通知管道

**管理後台**設定管道(Email / LINE / Slack / Discord / Telegram / Webhook),然後**員工自己去綁定**。

沒有通知管道,收件人永遠不知道東西到了 —— 那整套系統就只是一本比較貴的簿子。

### 另外:品牌與功能開關

`config/branding.yaml` 可以改公司名、Logo、主色、取件地點、保存年限,以及功能開關(交寄 / 代收貨款 / 冷藏 / 機密件 / 2FA…)。**不用改程式**。見 [BRANDING.md](BRANDING.md)。

## 櫃台:收到包裹怎麼登記

三種方式,依情境選:

### 拍照登記(最常用)

**選單 → 拍照登記**。用手機直接拍包裹標籤。

- 可以一件拍多張(正面 + 背面 + 破損處),系統會把它們歸為同一件
- 拍的同時會自動掃條碼/QR,掃到就把單號帶進來
- 支援 HEIC(iPhone 預設格式)
- **手機必須用 HTTPS 開**,瀏覽器禁止不安全來源存取相機。用 http 開的話相機頁會什麼都不做

拍完送出 → 進入**確認頁**。

### 批次上傳

**選單 → 拍照登記 → 批次上傳**。一次最多 30 張。

適合「早上一次到 20 件」的情況:先全部拍完,再一起上傳、一次確認完。上傳時可以框選多張合併為同一件。

### 手動登記

**選單 → 手動登記**。沒有標籤、或標籤糊掉、或就是懶得拍的時候。

所有欄位自己填,姓名一樣有模糊比對輔助。

## 確認頁:整套系統的關鍵一步

拍完照後會看到:左邊是照片(下面標著**拍攝於什麼時間**,從照片的 EXIF 讀出來的),右邊是 AI 填好的表單。

### 你要做的事

**看一眼,確認,送出。** 通常 3 秒。

- **黃底的欄位 = AI 對這格沒把握**,請特別看一下
- **收件人**下方會出現候選人 chips,每個標著信心程度
- 如果只有一位高信心候選,系統會自動幫你選好
- 如果有**兩位以上同樣高分**(例如公司有兩個「陳怡君」),系統**不會替你猜** —— 它會把候選留給你點。多按一下,總比一封信送錯人好

### 部門件

如果信是寫給部門而不是個人,把收件人切換成部門,選好部門 —— 系統會通知那個部門的固定聯絡人。

### 特殊標記

- **機密件**:勾了之後,只有管理員/櫃台看得到,而且**每次有人看照片都會留下稽核紀錄**
- **代收貨款(COD)**:填金額
- **冷藏**:標記後在收件台會特別顯示,避免放到壞掉

送出後,系統立刻通知收件人。

## 員工:怎麼收到通知、怎麼領

### 第一次:綁定通知管道

**選單 → 通知設定**。選管道(Email / LINE / …),系統給一組**綁定碼**,照畫面指示完成驗證。

沒綁定就收不到通知。這是每個新同事到職時該做的第一件事。

### 我的郵件

**選單 → 我的郵件**。看得到自己所有的件、狀態、以及螢幕上一組**大字的取件碼**。

### 領取

拿著取件碼去櫃台。或者直接報名字也可以。

## 櫃台:發放與核銷

**選單 → 領取核銷**。

1. **查詢**:輸入取件碼,或直接打對方的名字
2. 畫面列出這個人所有待領的件
3. **核銷方式**二選一:
   - **簽名**:對方在螢幕上簽,存證
   - **取件碼**:對方報碼,系統驗證
4. **代領**:如果不是本人來拿(同事幫忙帶),填上實際領取人的名字 —— 這一筆會記在紀錄裡

系統會記錄領取時間、領取人、核銷方式。三個月後有人問「那份合約誰簽收的」,查得出來。

---

## 交寄:公司要寄東西出去

**選單 → 交寄**。

1. **建立交寄單**:申請人(自己開的話會自動帶入)、部門、收件人資訊、承運商、付款方式、費用
2. 東西實際寄出後,點「**標記已交寄**」:
   - 手動輸入託運單號,或
   - **拍託運單照片**,讓 OCR 幫你讀單號
3. 系統通知申請人「你的東西寄出了,單號是 XXX」

## 查詢、報表、稽核

### 查詢

**選單 → 查詢**。關鍵字、狀態、日期區間、部門、承運商,點開有明細抽屜。

### 報表

**選單 → 報表**。選日期區間 + 分組方式(部門 / 承運商 / 日),會看到:

- 收件量、已領取、未領取、**平均領取時間(小時)**、交寄量
- 長條圖(旁邊一定同時有表格 —— 顏色不會是唯一的資訊載體)
- **匯出 CSV**:收件與交寄各一份

「平均領取時間」是個好指標:數字變大通常代表通知沒送到,而不是同事變懶。

### 稽核紀錄

**管理後台 → 稽核紀錄**(僅管理員)。

誰、在什麼時候、對哪一筆、做了什麼、從什麼 IP。可以看到改動前後的差異。這份紀錄是**唯讀且只能新增**的 —— 程式層面就禁止修改與刪除,不是靠約定。

## 網路斷了怎麼辦

**照常拍照登記。**

系統是 PWA,離線時會把件排進佇列,畫面上會顯示佇列數量。網路恢復後自動送出。

這是為了那種「櫃台在地下室、收訊很差」的現實情況設計的 —— 不該因為訊號不好就叫櫃台改用紙筆。

## 常見狀況

| 狀況 | 原因 |
|---|---|
| **手機相機頁沒反應** | 不是 HTTPS。瀏覽器禁止不安全來源存取相機 —— 這是最常見的問題 |
| **收件人一直對不上** | 名錄沒有這個人,或沒填別名/綽號 |
| **收件人欄位空白、要我自己選** | 有兩位以上同名同姓的高分候選。系統刻意不猜,請你點一位 |
| **AI 辨識失敗 / 很慢** | 金鑰額度、模型、或供應商當機。確認頁會顯示供應商回的真實錯誤訊息 |
| **同事說沒收到通知** | 他沒綁定通知管道,或該管道發送失敗(看**通知失敗清單**) |
| **部門件沒人被通知** | 那個部門沒有設固定聯絡人 |
| **看不到機密件** | 你的角色是「員工」或「唯讀」。這是設計如此 |
| **系統重新部署後被登出** | 正常。重啟會清掉記憶體中的 session,資料與金鑰不受影響 |
| **時間看起來怪怪的** | 全站一律以**台北時間**顯示,資料庫存 UTC |

還有問題見 [FAQ.md](FAQ.md),或系統內建的**使用說明**頁。

## 給導入者的一點建議

上線第一天,**先跑一件真的**:拍一個真包裹 → 確認 → 看通知有沒有到 → 領取簽名。

一次真實的完整流程,比任何檢查清單都更能告訴你這套系統在你的辦公室裡是不是真的能動。
