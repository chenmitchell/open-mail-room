# 01 需求規格

## 1. 角色(RBAC)

| 角色 | 權限 |
|---|---|
| admin | 全部:系統設定、AI Key、通知通道、員工名錄、使用者管理、稽核紀錄 |
| counter(櫃台) | 收件/交寄登記、批次上傳、OCR 確認、領取核銷、查詢報表 |
| employee(員工) | 查看自己的郵件、綁定通知通道、線上簽收(可選)、代領授權 |
| viewer | 唯讀查詢(如主管看部門統計) |
| API client | 依 API Key 綁定的 scope(見 03) |

## 2. 核心流程

### 2.1 收件(inbound)
1. 包裹/郵件到櫃台 → 櫃台用手機或桌機開啟 PWA。
2. 拍照(可連拍多件)或批次上傳既有照片。拍攝模式:預設「一張=一件」;可按「＋加拍同件」將多張照片(標籤/側面/箱損存證)歸為同一件;批次上傳時在確認頁可框選多張合併為一件。信件模式(mail_type=letter)提示可加拍信封背面(寄件人常在背面)。
3. 每張照片:前端 ZXing 先掃條碼取得單號(免 token)→ 後端 AI OCR 抽取:單號(補條碼沒掃到的)、承運商、寄件人、收件人、備註。
4. 收件人姓名對員工名錄做模糊比對(見 §5),自動帶出部門;比對信心低時列候選給櫃台選。
5. 櫃台逐筆確認/修正 → 儲存 → 自動發通知。
6. 員工領取:櫃台掃員工出示的取件 QR 或搜尋姓名 → 員工簽名(觸控手寫)或按取件碼核銷 → 狀態改「已領取」。
7. 逾期未領:n 天後自動再提醒(預設 2 天),m 天後標記「滯留」進報表(預設 7 天)。

### 2.2 交寄(outbound)
1. 員工或櫃台建立交寄單:申請人、部門、收件人資訊、承運商、付款方式(公司月結/部門代碼/自付)。
2. 交寄時拍託運單照片 → OCR 抽單號回填 → 狀態「已交寄」。
3. 可選:記錄費用做部門分攤報表。

### 2.3 批次
- 一次上傳最多 30 張照片,逐張排入 OCR 佇列,完成後進「待確認」清單,櫃台一頁式逐筆確認。
- 支援 CSV 匯入歷史資料、CSV/XLSX 匯出。

## 3. 櫃台紀錄欄位(調查台灣實務 + 商用產品規格彙整)

### 收件必填
流水號(系統產生,格式 `IN-YYYYMMDD-####`)、收到時間(預設現在)、運輸方式、收件人(對應員工→部門)、經手櫃台人員。

### 收件選填
郵件/託運單號、承運商(見 10 的通路表:中華郵政平信/掛號/包裹/快捷/i郵箱、黑貓、新竹、嘉里大榮、宅配通、順豐、DHL、FedEx、UPS、7-11 交貨便、全家店到店、機車快遞、其他)、寄件人姓名/公司/電話、郵件類型(信件/文件/包裹/箱/棧板)、機密件旗標(機密件不拍內容、通知不顯示寄件人)、貨到付款金額、需冷藏/冷凍、尺寸/重量、照片(1~5 張)、備註。

### 領取紀錄
領取時間、領取人(本人/代領人姓名)、簽名圖檔或取件碼核銷紀錄、領取時照片(可選)。

### 交寄欄位
流水號 `OUT-YYYYMMDD-####`、申請人/部門、收件人姓名/公司/地址/電話、承運商、託運單號、寄件時間、費用、付款方式、狀態(待交寄/已交寄/已送達/異常)、照片、備註。

### 狀態機(inbound)
`received → notified → picked_up`,分支:`returned`(退回)、`forwarded`(轉寄他址)、`unclaimed`(滯留)、`destroyed`(逾期銷毀,需 admin 且留稽核)。任何狀態變更寫 audit log。

## 4. 文件管理需求

- 全欄位可搜尋(單號、寄件人、收件人、部門、日期區間、狀態)。
- 照片與紀錄綁定,支援保存期限政策:預設保留 5 年(對齊個資法損害賠償時效,見 07/11),到期自動匿名化或刪除(可設定)。
- 匯出 CSV/XLSX;報表:每日/每月件量、各部門件量、平均領取時間、滯留清單、各承運商佔比。
- 稽核紀錄:誰在何時建立/修改/刪除/查看了哪筆(機密件查看也記錄)。

## 5. 員工名錄

- 欄位:姓名、別名/英文名(陣列,供 OCR 比對)、部門、分機、Email、通知綁定(LINE userId、Telegram chatId…)、狀態(在職/離職)。
- 匯入:CSV 必備;預留 SCIM/LDAP/Google Workspace 介面(v2)。
- 模糊比對:姓名正規化(全半形、繁簡、去空白)後用 rapidfuzz;分數 ≥90 自動帶入、70–90 列候選、<70 留空由櫃台輸入。離職員工的郵件標記警示,提示退回或轉交部門主管。

## 6. 非功能需求

- 穩定性:單機 docker compose 重啟自癒;所有背景工作(OCR、通知)有重試(指數退避,最多 5 次)與死信紀錄;健康檢查端點 `/healthz`;資料庫每日自動備份(容器內 cron → 本地 + 可選 S3 相容)。
- 效能:單張 OCR 往返 <15s;列表查詢 <500ms @ 10 萬筆。
- 安全:見 07-SECURITY.md(TLS 強制、靜態加密、RBAC、上傳驗證)。
- 無障礙:WCAG 2.2 AAA 對比、鍵盤可操作、Okabe-Ito 色盤(見 06)。
- 可套版:`config/branding.yaml`(公司名、logo、主色、語言、欄位開關、保留年限、通知模板)改完即用,不需改程式碼。

## 7. 明確不做(v1)

多租戶 SaaS、承運商貨態 API 自動追蹤(台灣各家 API 皆需契約申請,見 10;留 plugin 介面)、智慧櫃硬體整合、行動原生 App(PWA 取代)。
